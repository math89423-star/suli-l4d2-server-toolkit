# L4D2 si_hud 连杀奖励门槛坑（v1.7.54 修复）

## 现象（用户实测发现）

2 特感连杀结算显示"特感 x2、+194分"——用户质疑："我们不是第一档 20 分，一只特感 6 分吗？最起码也是 4 只特感啊？"

194 = 击杀分 38（正常入账）+ **错发奖励 156**。

## 根因

v1.7.53 阶梯奖励实现写 `if (hw > 0)` 就计价——第一段 0~20 人头也在计费：2 特感 hw=12 按 `12 × 1.3 × 10 = 156` 发钱。

**设计语义错位**：用户设计的"第一档 20 人头"是**门槛**（不够 20 人头不开闸），我实现成了"从 0 开始计费的电费阶梯"。用户预期：20/6 = 3.33 → 至少 4 特感才触发。

## 修复（v1.7.54）

`if (hw > 0)` → `if (hw >= g_cvStreakHwL1.IntValue)`（l1 = 20）：

- hw < 20 → 奖励 0（2 特感 hw=12、3 特感 hw=18 都不开闸）
- 达到门槛后**全段计价不变**（hw=24 → 320 = 20×13 + 4×14.5，用户认可的例子）

## 教训

**分段/阶梯计费类设计，先确认第一档边界的语义**：是"开闸门槛"（不到不给钱，到了从 0 全段计）还是"第一计费段"（0 开始就有单价）？用户说"类似电费"时两者都可能。验证锚点：用用户给过的数值例子反推（hw=24→320 必须是全段计价，但 hw=12 必须为 0 → 门槛制）。
